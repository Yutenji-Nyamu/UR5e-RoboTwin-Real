# 运行与后续检查

工作区：`/data/chenyiteng/projects/geowam-real`。下列命令在工作区运行，Python 固定为 `envs/preprocess/bin/python`。

## 看当前训练

```bash
CUDA_VISIBLE_DEVICES= envs/preprocess/bin/python repos/UR5e-RoboTwin-Real/scripts/geowam/monitor_training.py
```

查看 `runs/training_health.json`、`runs/train_rgbd72_v1/STATUS.md` 与 `training_curves.png`。正常情况下步数递增，loss/gradient 保持有限，约每小时新增一个带 `complete.json` 的检查点。初始学习率逐步打开，日志中的不同步采用不同噪声强度，结合移动平均及固定样本拟合曲线观察。

## 看实际拟合输出

每个检查点生成 `vis/step_XXXXXXX/<task>_physical_actions.png`：六关节和夹爪各自的完整 32 步预测/记录曲线。`scalars.json` 提供关节弧度 MAE、夹爪准确率、视频/Track latent 误差。

```bash
CUDA_VISIBLE_DEVICES= envs/preprocess/bin/python repos/UR5e-RoboTwin-Real/scripts/geowam/decode_fit_predictions.py
```

该入口已用 smoke 检查点实际完成 CPU 解码；默认解码最近一次五任务预测，输出 `<task>_decoded.jpg` 与预测帧条，训练继续占用 6/7 卡。图中 `gt` 为记录数据的 VAE 解码，`pred` 为模型生成；每个完整预测条包含 9 帧。可用 `--step 1234 --tasks block_drawer` 指定检查点和任务。

## 续训

启动器持有 `runs/training.lock`，状态保存在 `runs/training_status.json`，包含监督进程、每次启动的 PID、启动时间、GPU UUID 和日志。故障时先核对进程身份与完整检查点，再运行：

```bash
CUDA_VISIBLE_DEVICES= envs/preprocess/bin/python repos/UR5e-RoboTwin-Real/scripts/geowam/run_training.py train
```

入口自动选择最近完整检查点，保留已有输出与最多三次启动记录。数据清单、预处理配置与 QA 标记通过校验后启动。两卡固定为物理 6/7；RLT 已交接，本任务调试与恢复优先；其他卡的工作独立运行。
