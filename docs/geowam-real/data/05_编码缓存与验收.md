# 编码缓存：模型实际读取什么

## 从一段记录生成一个样本

| 内容 | 输入形式 | 用途 |
|---|---|---|
| RGB 视频 | 当前及每隔 4 帧，共 9 帧；head 320×192 在上，wrist 在下 | Video 监督 |
| Track | 当前前景灰色锚点＋8 个 t→t+4 位移图 | Track 监督 |
| 当前条件 | 主视角当前 RGB、实测 depth、前景 mask | 推理条件 |
| 动作／状态 | 未来 32×7 动作、当前 7 维状态及维度 mask | Action 监督与输入 |
| 角色／运动标签 | 本体／物体角色和位移的空间汇总 | 辅助监督 |
| 进度 | 窗口起点在整段示范中的归一化位置 | 进度监督 |
| 文本 | 任务指令经过 UMT5 编码 | 任务条件 |

冻结的 Wan VAE 把 RGB／Track 压成 latent。RGB 样本为 48×3×24×20；Track 为 48×3×16×20，主视角 Track 从 320×240 中心补到 320×256 后编码。当前条件分别保留单时间位置。

## 文件结构

```text
cache/real_v1/
  normalization.json / depth_stats.json / text_context.pt
  episodes.json / cache_audit.json
  manifests/<task>.jsonl / all.jsonl
  <episode>/
    metadata.npz / masks_full.npz / geometry.npz / geometry.json
    latents.json / manifest.jsonl
    latents_<内容签名>/sXXXXX.pt
    mask_review.jpg / flow_review_*.jpg / vae_review_*.jpg
```

JSONL 清单指向实际使用的 .pt。修复后重新生成的目录以内容签名区分；Release 只取当前清单引用的 2,405 个窗口。
