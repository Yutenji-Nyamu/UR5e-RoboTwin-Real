### 时序核对边界

- 11条都没有 sync 中引用但缺失的图像文件；close/open 都在旧 crop 内，每条只有一次 close、一次 open。
- 每条开头有一次0.2秒间隔，均落在被裁掉的起始静止段；只有 `165840` 还在动作中有0.3秒间隔。
- raw robot time 与 sync 文件对应时间的最近邻误差为0，是因为 sync 用同一控制器时间写入；**不能据此声称相机曝光与机械臂硬件零延迟同步**。
- `165840` 是暂不纳入最小参考集，不是删除文件/撤销 success；未来可在明确时序策略下处理。

## 3. 首尾静止：能裁，但尾部需要保护夹爪完成

旧规则是按与起始/最终状态的偏离找活动边界，不是移除全部低速帧。它保留中途对齐、接触、抓取等待；此原则继续保留。

发现的问题：二值 gripper_state 在 **open 命令发出** 时就变0，但实体夹爪仍需时间张开。旧裁剪通常只留下 open 后0.2秒。对 `164924/165301/165418/170000` 的 open+0/+2/+5/+10/raw-end 图像比较可见，open+2 时释放动作还在进行；open+10 已呈现完整张开/方块留在桌面的状态。

因此建议：

1. 起始静止仍用运动阈值并保留3帧上下文；不要去掉抓取前最后接近段。
2. 尾部取“运动结束保护段”与“最后 open 后1秒”中较晚者，必要时按图像完成情况延长。
3. 保留中间停顿、close/open，以及释放完成画面；不把人体摆场前后空白混入训练。
4. 只导出新版本，记录 exact run IDs、crop bounds、阈值、source hash；raw、旧 DP Zarr/checkpoint 均不动。

这些规则也用于新 joint 数据，但运动检测新增关节位移依据，不能把 q 当 TCP 用2mm阈值。可综合 q、TCP 和 gripper event 标识活动，阈值以补采噪声确认。

## 4. joint 首版补采要求（下一轮执行）

- 先改好同包 q/TCP 双记录和 schema，再采；不能先重复旧 collector，最后才发现仍没有关节角。
- 第一条先验证 CSV 每行 q/TCP/time、图像对数、gripper events、manifest，验证通过再连贯采另外4条。
- 同一初始关节姿态、相同工具/TCP 配置、相同摆场；缓慢平顺地抓取→抬起→放下→开爪，开爪后等约1秒再结束。
- 先5条成功即可作为最小 SFT 数据，不要求泛化场景/多任务扩增，也不强制从5条中扣出验证集。
- 每条都看一次关键帧与关节/时间指标；中断/失败保留原始记录但不混作成功标签。
- 新数据使用实测 `actual_q`，不用 `target_q` 代替自由拖动中的实际示教，不把旧 TCP 的 IK 估计写成 actual_q。

新数据 ID、帧数和裁剪区间只有采完才能确定；不得把本表中的旧 TCP 数字写成 joint 训练规模。

## 5. 本轮审计方式

复用了当前实现的 `_aligned_session`、`tcp_gripper_vectors` 和 `motion_bounds`，读取20个 session 的 CSV/manifest；计算时间间隔、缺帧、夹爪事件、crop、路径长度与跳变量，再查看11条关键帧和4条释放尾段。
